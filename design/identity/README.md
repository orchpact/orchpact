# Orchpact 序契 · 视觉配色标准

**版本 1.0.0 · 2026-11-27**　本标准适用于 Orchpact 官网、管理后台（含登录与工作流画布）和文档站。新页面、组件和后续改版均沿用同一组语义变量。每个站点根据用途分配颜色，品牌图标始终使用同一份母版。

[打开三站明暗样张](preview.html) · [查完整色值与用途](tokens.json) · [引用 CSS](tokens.css) · [选品牌素材](brand/README.md) · [按现有代码迁移](MIGRATION.md)

## 品牌的四种基础色

| 颜色 | sRGB | 在品牌中承担的角色 |
| --- | --- | --- |
| 靛蓝 | `#262896` | 图标底、官网品牌区、浅色界面的主操作。为荧光黄提供稳定的深色背景。 |
| 荧光黄 | `#EAFF58` | 标识中穿过验收关口的勾和交付节点。界面中用于明确已获最终验收的交付标记。 |
| 纸白 | `#F7F4EB` | 靛蓝底上的节点、依赖线、反白文字和深底字标。 |
| 墨黑 | `#181922` | 浅色正文、浅底字标，以及荧光黄底上的文字和图形。 |

观察验收勾时，荧光黄与靛蓝的对比度为 **10.37∶1**，与白底仅为 **1.11∶1**。在浅色表面，用墨黑勾和「交付已验收」文字落在小块黄底上（**15.77∶1**），或把黄勾收进靛蓝标记中。荧光黄一旦同时用于导航、普通 CTA 和提示灯，读者便很难分清哪一步真正完成了交付。

## 三个站点如何分配颜色

| 场景 | 主要表面与阅读层 | 操作与导航 | 荧光黄出现的位置 |
| --- | --- | --- | --- |
| **官网** | 中性浅底介绍产品；首屏可用大块靛蓝承载标志、纸白标题与工作流演示。终端使用代码配色。 | 中性底上用靛蓝主按钮。靛蓝展台上的主按钮使用纸白底、靛蓝字；用纸白焦点环与展台拉开距离。 | 首屏演示中穿过验收关口、抵达结果的勾与交付点。演示的结果应标为示例。 |
| **后台** | 工作画布用 page，表单、节点和表格用 surface；侧栏、悬停行用 subtle。长时间操作以中性色为主。 | 主操作用 action，当前导航用 selected-bg＋link＋当前位置标识。节点选中用描边和选中标签，依赖箭头使用 edge。 | 已验收交付详情中最多一个主要黄标。列表中的运行状态、审批和错误使用业务语义色。 |
| **文档站** | 阅读区用 surface，侧栏用 page/subtle。目录、正文、代码块和面包屑保持清晰层次。 | 正文链接用 link 并加下划线；已访问用 link-visited。当前目录用选中底、标记线及 `aria-current`。 | 工作流图中有明确验收记录的终点，或正文引用品牌标识时。语法高亮、搜索命中和警告各有自己的样式。 |

后台和文档默认跟随系统明暗偏好，显式选择优先。官网可固定浅色阅读背景，让靛蓝展台在两种模式下均保持品牌三色。反白字标按**所在表面的实际颜色**选择，例如浅色页面上的靛蓝页脚也用深底版字标。

## 组件用色速查

变量统一带 `--op-` 前缀。以下给出常用搭配，完整的 39 个角色及其用途见 [tokens.json](tokens.json)。

| 对象 | 建议变量 | 浅色 | 深色 |
| --- | --- | --- | --- |
| 页面 / 面板 | page / surface | `#F7F7FA` / `#FFFFFF` | `#141520` / `#1D1E2D` |
| 标题正文 / 次级文字 | text / muted | `#181922` / `#505569` | `#F6F5FA` / `#B5B7CA` |
| 主按钮底 / 字 | action / on-action | `#262896` / `#F7F4EB` | `#BCBDFF` / `#17182B` |
| 当前导航底 / 字 | selected-bg / link | `#E8E9FF` / `#3033A3` | `#30315A` / `#BDBEFF` |
| 装饰分隔 / 必要控件边界 | line / control | `#D4D7E1` / `#71768A` | `#37394D` / `#878BA3` |
| 工作流默认边 / 选中边 | edge / edge-selected | `#60677F` / `#262896` | `#A3A8C0` / `#CDCCFF` |
| 焦点环 | focus | `#4744B8` | `#C7C5FF` |
| 代码块底 / 正文 | code-bg / code-text | `#1A1B2B` / `#F4F3FA` | `#10111B` / `#F4F3FA` |

主按钮依次使用 action、action-hover、action-active；禁用使用 disabled-bg / disabled-fg，并提供原生 disabled 或等价语义。输入错误给出文本原因、定位到字段，配合 danger 色。破坏性操作写清动作名称；如用实心危险按钮，可以用 danger-fg 作底、danger-bg 作字，两者的对比与提示块相同。表格选中同时提供勾选框或行首标记。

画布中的普通依赖使用实线与箭头，分组边界用虚线，选中节点增加外框和可读名称。连接线上承载信息的部分以不透明 edge 色绘制。线和边框尽量轻，关键交互路径须在实际显示比例下辨认；必要时扩大命中区域。

## 产品状态有各自的语义

| 类别 | 浅色字 / 底 | 深色字 / 底 | 产品中的文字与标记示例 |
| --- | --- | --- | --- |
| neutral | `#4B5063 / #ECEEF4` | `#D5D7E5 / #303242` | 时钟「等待执行」、横线「已取消」、文字「运行完成」。运行结束和验收决定分开显示。 |
| info | `#214B90 / #E7EFFF` | `#BCD6FF / #202F4B` | 播放标记「执行中」、说明提示。 |
| success | `#155B48 / #E2F4EB` | `#A0E6C8 / #18382E` | 普通勾「检查通过」；规则 PASS 表示相应检查取得通过结果。 |
| warning | `#744600 / #FFF0D0` | `#FFDC9E / #412F18` | 问号「证据不足」、待办标记「待验收」「外部操作待审批」「结果待核对」。 |
| danger | `#973037 / #FCE8EA` | `#FFB8BA / #47272E` | 叉号「执行失败」「验收拒绝」，保留具体原因。 |
| 最终验收 | 品牌黄底、墨黑字 | 品牌黄底、墨黑字 | 验收记录确认后显示「交付已验收」与勾。黑白打印时仍能凭文字区分。 |

状态所指对象要出现在附近。例如同一次运行可以同时显示「规则检查通过」与「交付待人审」。文档的注意事项用 warning，信息说明用 info，示例中的成功返回用 success。语法着色分别使用 code-keyword、code-string 和 code-comment；命令与返回值通过换行、提示符或说明加以区分。

## 接入与维护

1. 引擎仓库的 `design/identity/` 保存发布源；官网仓库的同名目录保存同版本快照，供官网和文档站共用。每个仓库独立构建。实际网页从本仓库的静态路径加载 CSS、SVG 或 PNG。
2. `tokens.json` 是色值的编辑入口。`tokens.css` 是生成物；组件使用语义变量，例如 `background: var(--op-action)` 和 `color: var(--op-on-action)`。品牌展台及官方图标使用固定品牌色。
3. 新增前先核对已有角色。确有新的交互含义时，同步提供明暗值、用途、对比检查和实际组件样张。修订增加版本号；向两个仓库分发同版本文件，并更新正在使用的本地静态副本。字标、图形或裁切变化需重新导出相应 PNG / ICO 并复核小尺寸。
4. 单独打开 `preview.html` 可离线查看。默认跟随系统；在 `<html>` 上设置 `data-op-theme="light"` 或 `"dark"` 可指定主题，移除属性恢复系统。局部反色样张也可在容器上使用该属性。
5. 合并视觉改动前对照三站样张，检查桌面/窄屏、键盘焦点、普通/悬停/按下/禁用、长文链接、代码、运行与验收状态。文档另看打印和系统强制颜色。图标单独呈现时提供可访问名称，旁边已有等价文字时用装饰图像。

在规范目录内运行，使用 Python 标准库：

```sh
python3 validate.py               # 只读，检查 CSS 与来源一致，并核对两种主题的前景/背景组合
python3 validate.py --report      # 输出每一组对比度
python3 validate.py --write-css   # 修改 tokens.json 后重新生成 CSS
```

正文、链接及状态文字按至少 **4.5∶1** 设计。必要控件边界、焦点指示与承载信息的图形按至少 **3∶1** 检查相邻背景。默认焦点环可用 2 px 实线、向外偏移 3 px；置于品牌区时改用纸白环，在浅色按钮和深色展台之间留出间距。当前校验覆盖不透明角色的约定组合。图片叠字、玻璃面板、叠加透明度及动态 SVG 要按最终合成背景另验。所有状态附上文字或形状。[WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [非文本对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) · [颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)
