02 / BINDING

应用引用，空间绑定。

多个独立应用固定引用同一工作流修订；各空间再选择本地模型，保留各自的账号与运行边界。

固定修订 → 独立应用 → 空间模型应用引用更新与空间安装升级分别确认
03 / EXECUTION

每次执行独立留痕。

本次输入、付款人、调用、产物与验收分别记录；共享定义不会混合运行权限和费用。

定义指纹 + 绑定快照旧执行保留原版本，定义升级显式进行

管理台、API 与客户端提供不同入口。当前执行能力围绕模型协作和文件交付；人工资格解析与通用异常分支语法仍在完善。

03 / ACCOUNTABLE BY DESIGN

每次行动，
都有明确的边界。

从发起委托到恢复中断，保留责任、版本和依据。

BEFORE / 01

授权限定行动。

调用能力受角色与授权共同约束。转授只能收窄范围；父授权撤销后，后续子授权行动也会失效。

动作能力期限额度
DELIVERY / 02

验收绑定版本。

产物不可覆盖。审校与人工验收绑定具体文件、哈希和版本；修订后的成果需要对应的新验收。

初稿→修订稿重新验收
RECOVERY / 03

恢复尊重事实。

先预留，再按实际回执结算。费用不确定时保持预留；重启先恢复回执，避免自动重发带来的重复费用。

未知结果 → 核对回执 → 再作决定

确定性契约校验由平台规则完成；专业审校作为独立工作项配置。项目可以保留部分成果，并明确列出尚未完成的缺口。

EXECUTABLE CONTRACTS

让规则可以被验证。

四类行为，七项回归。
检查执行边界，保留可审阅的结果。

  1. 01 / 授权越权转授被拒绝

    权限不能扩大，父授权撤销后子授权行动失效。

  2. 02 / 验收旧验收不能放行修订稿

    验收绑定具体产物、哈希与执行代次。

  3. 03 / 恢复未知结果不自动重发

    保留原付款人和预留，先核对真实回执。

  4. 04 / 账务重复回执只结算一次

    记录重复到达，仍遵守同一幂等边界。

OPERATING MODEL

一个主进程。数据库与文件目录成对绑定；独占锁在初始化前获得，业务、账务和审计在同一事务里提交。

了解当前边界 +

当前实现面向单机、单主进程，尚未提供远程 Worker、多主调度或第三方代码沙箱。生成的代码作为文件交付，不由平台自动执行、安装或部署。

专业审校可能产生独立模型调用；内部积分是计量标准，不等于供应商金额。这里展示的是执行机制，实际内容质量需要用真实任务单独评估。
