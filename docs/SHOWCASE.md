# 官方网站与实例介绍页

Orchpact 的公开介绍围绕声明式工作流、CrewAI 团队执行和平台治理边界展开。官方网站与随服务发行的实例介绍页分别维护，均采用原生 HTML/CSS/JavaScript。

## 官方网站

[orchpact.github.io](https://orchpact.github.io/) 由独立的 [官网仓库](https://github.com/orchpact/orchpact.github.io)构建和发布。首页以“定义协作的结构，守住执行的边界”为主线，使用架构手册式布局说明：

- Orchpact 工作流层与 CrewAI 团队层的责任分工，每次执行创建独立运行对象。
- 定义发布、应用固定引用、Workspace 资源安装与执行快照四个边界。
- 团队声明、安装绑定和运行记录片段的代码浏览器。
- 正常交付、定向返工、外部结果未知三类可逐步浏览的本地事件示意。
- 权限、额度、产物身份、验收、回执与结算约束，以及单主进程的 PostgreSQL 和文件持久化模型。

在线技术文档来自本仓库的明确提交；官网保存逐文件哈希和来源提交，构建不读取相邻目录或用户实例。README 与技术原文在本仓库维护，官网通过同步脚本导入白名单内的技术文档，README 保留在主仓库并由链接访问。两仓库边界和操作命令见 [仓库组织](REPOSITORIES.md)。

## 随服务发行的实例介绍页

实例介绍页独立于官网构建，不负责发布官网。它提供工作流机制介绍与本机管理入口，没有 npm 构建步骤。下文描述其路由与维护约束。

### 内容与入口

- 可移植定义包含职责、依赖与验收规则；多个独立应用固定引用同一修订，各空间再绑定自己的模型资源。
- 发布定义、移动应用引用、升级空间安装与发起执行分别进行，旧执行保留来源与资源快照。
- 职责、项目参与和行动授权分别说明，组织隶属关系不自动授予权限。
- 固定计划与自主规划进入同一任务图。交互示例展示顺利交付、定向返工和结果待核定。
- 返工保留初稿并重新审校；未知外部结果保留预留，不自动重发。
- 架构图说明 kernel、services、adapters 和 interfaces 的边界；持久化采用 PostgreSQL 与配套文件，保持单主进程。

平台入口 `/` 和 `/about/` 读取 `src/orchpact/static/showcase/`，管理台入口为 `/admin/`。产品域名不开放宣传页与管理资源。宣传页不读取账号、项目或后台 API，不保存业务数据；交互展示值使用 textContent 与原生 DOM 节点。

页面随服务和 wheel 一起发行，不依赖任何相邻产品或独立站仓库。单独托管时需自行保持 `/about/` 的静态资源映射；本仓库不自动部署站点。修改源文件后按 [发行验收](RELEASE_VALIDATION.md)验证站点路由与前端脚本，浏览器另行核验桌面/手机布局、锚点、复制反馈和动画停止行为。

页面中的执行轨迹和状态均为机制示意，不证明模型质量、检索能力、真实价格或生产运行结果。已实现范围见 [架构](ARCHITECTURE.md)，公开接口和版本承诺见 [公开接口](COMPATIBILITY.md)。
